# 営業デモをワンタッチで準備する

## 営業担当者の使い方

開発担当者が導入したら、デモログインの「営業デモをまとめて準備する」を開きます。入口は `/demo/sales` です。

1. 自分用のセット番号を選び、「この番号にする」を押す。担当者ごとに別の番号を決めておきます。
2. 見せたい場面の「この場面を用意する」を押す。
3. 完了メッセージが出たら、「お店の紹介」「候補者を探す」「あかりとのトーク」などを開く。実演用アカウントへのログインも自動です。
4. 場面を切り替えるときは、ブラウザの「戻る」で準備画面に戻り、次の場面を用意する。

同じセット・同じ場面をもう一度選ぶと、実演中に変えたトークや採用・ボーナスの状態を戻せます。同じ番号を複数人で同時に使わないでください。20セットまで用意できます。

| 場面 | 用意する状態 |
| --- | --- |
| 最初から商談 | あかりは声かけ前。みおは相互KEEP・返信済み。プロフィール、検索、KEEP、初回スカウトの説明に使用 |
| 面談日が決まった場面 | あかりとの挨拶・返信・候補日の提案・日時確定。面談日は準備日から2日後 |
| 採用後・請求の場面 | あかりの本入店が決まり、条件達成・申請・店舗承認・請求書発行まで進んだ状態 |
| 本人が受け取った場面 | 上記に加え、店舗入金報告・入金確認・キャスト振込・受領完了の履歴まで用意 |

店舗・キャスト3人の紹介、画像、希望条件、求人、店長メッセージも一緒に用意します。画像は同梱の実演用イラストで、実在する会員の写真は使いません。面談日や請求期限は準備日に合わせます。

営業台本は「最初から商談」→「面談日が決まった場面」→「採用後・請求」→「本人が受け取った場面」の順で進められます。後半へ切り替えるときは「ここからは同じ方の採用後の場面です」と説明してください。返信や入金の実行を待つ必要はありません。

正式な料金表、端末の充電・通信、訪問先が実際に登録するときの情報・写真は別途必要です。

## 開発担当者による初回導入

新しいコントローラ・サービス・データ定義・コマンド・Blade・設定・ルートと、`public/assets/images/demo-sales/` の4画像、ビルド済みCSSをデモ環境に配置してください。DBのテーブル追加・マイグレーションはありません。

デモ環境の設定例：

```dotenv
APP_ENV=demo
APP_URL=https://demo.misechoku.jp
DEMO_MODE=true
DEMO_SALES_ENABLED=true
```

有効化には両方のフラグ、許可された環境名（local/testing/demo/staging）、許可ホストが必要です。production環境や本番ホストでは動きません。ホストの許可リストは `config/demo.php` の `sales_hosts` にあります。この機能は既存のデモログインと同様、パスワード認証を省いた実演用機能です。実会員のDBを接続した環境には有効化しないでください。

配置・設定変更後、デモ環境でキャッシュを更新します。

```text
php artisan config:clear
php artisan route:clear
php artisan view:clear
php artisan cache:clear
```

その後 `/demo/sales` のボタンからデータを作成できます。SQLの事前投入は不要です。アプリのコードとDB構造は `database/mock_demo.sql` に対応している必要があります。業種1「キャバクラ」と性格タグ37・40・45が必要です。

プログラムは現在のBasic機能を使う実演用です。Premium契約、実際の許可証・本人確認書類、銀行口座、実際の請求メール、実際の送金は作成・実行しません。店舗の公開に使う審査ステータスのみ、実演用に承認済みにします。金額10万円＋手数料1万円＝11万円も架空の説明値です。

## コマンドで用意する場合

既定は内容確認だけで、DBへ接続しません。

```text
php artisan demo:sales --slot=1 --scene=start
```

開発担当者が、確認したデモ環境で実際に作成・復元する場合：

```text
php artisan demo:sales --slot=1 --scene=start --write
php artisan demo:sales --slot=1 --scene=interview --write
php artisan demo:sales --slot=1 --scene=invoice --write
php artisan demo:sales --slot=1 --scene=completed --write
```

## MySQL 8.0向けSQL

セット1・最初から商談の初回投入用SQLを `database/demo_sales_initial.sql` に用意しています。必要なら開発担当者が対象のデモDBを確認して実行してください。実行済みのセットや番号の競合があれば投入をスキップします。すでにあるセットの復元には画面またはコマンドを使用します。

別のセット・場面のSQLを、DB接続なしで書き出せます。日付も書き出した日に合わせるため、利用日が変わったら再出力してください。

```text
php artisan demo:sales --slot=2 --scene=completed --sql=database/demo_sales_slot2.sql
```

SQLは初回INSERTのみです。エラーが出たらROLLBACKし、原因を修正してから実行し直してください。エラー後に続行する `mysql --force` は使わないでください。準備画面・コマンドの作成処理はトランザクションでまとめ、失敗時は戻します。

## 復元の範囲と確認

- メールアドレスは `@sales-demo.invalid`、IDは専用の予約範囲です。同じ番号に別の所有者のデータがあれば、変更前に中止します。
- 同じセットの作成処理は排他制御します。トーク・KEEP・ブロックは、そのセットの店舗とキャスト3人の組み合わせだけを復元します。
- 採用・入金・振込作業・履歴は、そのセットの求人とキャスト3人の案件に限定して復元します。ほかの店舗・会員・営業セットは対象にしません。
- キャストの実演用画像・ひとこと・希望条件・タグ、店舗画像、対象アカウントの通知設定を作り直します。対象アカウントのプッシュ購読は解除します。
- 本処理はビジネス通知や送金のサービスを呼びません。イベントを発火させず架空データを保存し、対象キャスト・店舗担当者の外部通知設定を無効にします。
- 実演用アカウントで通常の画面から追加したデータのうち、上記以外（レビュー、Premium契約など）は復元対象外です。用意した場面の範囲で使用してください。

検証はDBへ接続しないテストで行います。今回、実DBへの投入は実行していません。初回配置後、開発担当者が4場面の作成・再作成、2セット間の独立性、各実演画面を確認してください。

```text
php vendor/phpunit/phpunit/phpunit tests/Feature/Demo
```

## 今回の品質確認

- DBへ接続しない15件のテスト、2,336項目の検証が通りました。4場面のスキーマ整合、20セットの番号の独立性、面談メッセージの対応、請求額と履歴、日付更新、通知設定、利用環境の制限、入力検証を確認しています。
- 実際のBladeから画面を生成し、320×700、390×844、768×1024、820×1180、1180×820の5サイズで確認しました。主要操作は44px以上の押せる範囲があり、ページの横はみ出しはありません。
- 準備ボタンの連打防止と、ブラウザで戻ったときのボタン復帰を確認しました。画面確認に使ったファイルと画像は `docs/internal/demo-sales-qa/` にあります。
- PHP構文、3つの追加ルート、CSSビルド、内容確認コマンド、SQL出力も確認しています。DBでの作成・復元、実際のアカウントでの画面遷移は、デモ環境へ配置後に確認する範囲です。
