# ミセチョク シナリオテストケース

テスター向けの手動シナリオテスト一覧。画面遷移（導線）を一通り網羅することを目的とする。

- 対象環境: demo.misechoku.jp（またはステージング）
- 実施前に **ハードリロード（Ctrl+F5）** でCSS/JSキャッシュを更新すること
- 「結果」列に `OK` / `NG` / `対象外` を記入し、NG の場合は備考に再現手順・スクリーンショットを添える

---

## 1. テスト観点の整理

各テストケースには以下の観点タグを付与している。NG 判断の基準として参照すること。

| タグ | 観点 | 確認内容 |
|------|------|---------|
| 機能 | 機能正常系 | 操作した結果、期待どおりデータ・画面が変化するか |
| 異常 | 異常系・バリデーション | 不正入力・二重操作・必須漏れが適切なエラーメッセージで弾かれるか（500エラーや無反応にならないか） |
| 権限 | 認可・アクセス制御 | 未ログイン／他ロール／権限なしスタッフでのURL直打ちが 403 またはログインへ誘導されるか |
| 表示 | 表示・UI | レイアウト崩れ、文言、件数バッジ、ステータス表示が正しいか |
| SP | レスポンシブ | 幅 375px（スマホ）/ 768px（タブレット）でも操作が完結できるか |
| 通知 | 通知連動 | 操作後に相手側のインボックス通知・Push・バッジが更新されるか |
| 整合 | データ整合 | 一連の操作後、関連画面（一覧・詳細・ダッシュボード・タスク）の表示が矛盾しないか |
| ログ | 監査ログ | 管理者の重要操作が「操作ログ」（/admin/admin-accounts/operation-log）に記録されるか |
| 回帰 | 回帰確認 | 直近の不具合修正が再発していないか（★印） |

優先度: **A**=リリース前必須 / B=主要導線 / C=補助導線
